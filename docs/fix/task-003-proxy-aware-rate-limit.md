# Task 003: レート制限に使うクライアントIPの信頼境界を修正する

- 観点: セキュリティ
- 優先度: High

## 問題

`views/utils.py:get_client_ip` は `CF-Connecting-IP` と `X-Forwarded-For` を無条件に信頼します。アプリへ直接到達できる構成、または上流がヘッダーを上書きしない構成では、攻撃者が任意IPを指定してパスワード試行・問い合わせ・AI利用のレート制限を回避できます。

## 実装指示

1. 信頼するプロキシのCIDRまたはホップ数を設定として明示する。未設定時は `REMOTE_ADDR` のみを使用する安全側の既定値にする。
2. `REMOTE_ADDR` が信頼済みプロキシの場合だけ転送ヘッダーを解釈する。
3. Cloudflare利用時は、オリジンへの直接アクセス遮断もデプロイ設定として文書化する。
4. IPを取得できない場合に全利用者が同じ空キーを共有しないよう、拒否または安全な代替キーを定義する。
5. 新規環境変数を追加する場合はREADMEまたはAGENTS.mdに用途と任意/必須を記載する。

## テスト

- 非信頼送信元の偽装ヘッダーが無視される。
- 信頼済みプロキシ経由では正しいクライアントIPを得る。
- IPv4、IPv6、不正値、複数XFF、空の `REMOTE_ADDR` を網羅する。
