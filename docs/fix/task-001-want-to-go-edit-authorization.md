# Task 001: 行きたい場所APIの編集認可漏れを修正する

- 観点: セキュリティ
- 優先度: Critical

## 問題

`WantToGoMapView.post` と `WantToGoV2View.post` は、閲覧認証しか行わず、行きたい場所の追加・更新・削除を実行します。編集パスワードが設定されていても、共有トークンを知る閲覧者がデータを改変できます。

対象: `tabisync/views/want_to_go.py` の両クラスの `dispatch` / `post`。同ファイルには同一CRUD処理が二重実装されています。

## 実装指示

1. 更新処理を単一の関数または編集専用Viewへ集約する。
2. 全ての変更操作で、編集パスワードがある場合は編集認証セッションを必須にし、未認証ならJSONで403を返す。
3. 閲覧ページのPOSTを廃止できるなら405にし、編集URLだけを更新先にする。
4. JSON不正、未知のaction、存在しないIDを400/404として一貫して返す。
5. `Itinerary` で絞り込む現在のオブジェクト所有権チェックは維持する。

## テスト

- 編集パスワードあり・編集未認証でcreate/update/deleteが全て403となり、DBが変化しない。
- 閲覧認証だけでは変更できない。
- 編集認証後は各操作が成功する。
- 別しおりの `WantToGo.id` は更新・削除できない。
- パスワードなしのしおりに関する現在の仕様を明文化し、回帰テストで固定する。
